# ドキュメントレビュースキル

docs/ 配下の全ドキュメントを横断的にレビューし、問題を報告する(修正は指示があるまで行わない)。

## 手順

### 1. レビュー実行

`doc-reviewer` サブエージェントを起動し、以下の観点でレビューさせる:

1. **ID 整合性**: 参照されている REQ/FR/NFR/SCR/T の ID が定義元に存在するか。定義されているが下流から一度も参照されていない Must 要求・要件はないか
2. **記入漏れ**: `{/* TODO` コメントの残存箇所、「例:」のままの記入例、`¥0` のままのサマリー
3. **上下流の整合性**: 要求の「対象外」が見積もりの「除外事項」に反映されているか。設計の環境構成と運用費用のインフラ費用が一致しているか。Must 要求がすべて FR/NFR でカバーされているか
4. **frontmatter・ステータス**: frontmatter の title/description の有無、frontmatter への独自フィールド混入(Blume がビルドから除外するため禁止)、本文冒頭のステータス行(`> ステータス: **draft**`)の有無と妥当性(下流が approved なのに上流が draft 等)

### 2. 補完チェック

サブエージェントの結果に加えて、自分でも以下を確認する:

- `npx markdownlint-cli2 "docs/**/*.{md,mdx}"` を実行し lint エラーを確認
- `npx blume build` が通るか確認(壊れたリンク・mermaid 構文エラーの検出)

### 3. 報告

問題を重要度順に一覧で報告する:

- **Critical**: 顧客提出をブロックする問題(Must 要求の要件漏れ、見積もりと設計の不整合、金額サマリー未記入)
- **Warning**: 提出前に解消すべき問題(TODO 残存、ID 参照切れ)
- **Info**: 品質向上の提案

各問題にはファイルパスと該当箇所を明記する。修正の実施はユーザーの指示を待つ。
