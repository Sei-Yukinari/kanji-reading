# ドキュメント作成ワークフロールール

## 作成順序

ドキュメントは必ず上流から下流の順で作成する:

1. **要件定義** (docs/requirements/) — プロジェクト概要 → 要求定義 → 要件定義
2. **設計** (docs/design/) — 要件定義の FR/NFR を入力とする
3. **見積もり** (docs/estimate/) — 要件定義と設計を入力とする

下流のドキュメントを作成する前に、上流ドキュメントに重大な `<!-- TODO -->` が残っていないか確認し、残っている場合はユーザーに知らせる。

## トレーサビリティ

- 機能要件(FR)・非機能要件(NFR)には必ず対応する要求 ID(REQ)を紐付ける
- 設計上の判断(画面・技術選定・アーキテクチャ)には根拠となる FR/NFR を紐付ける
- 見積もり WBS の各タスクには対応する要件 ID を紐付ける
- 存在しない ID を参照しない(/doc-review で検出される)

## 上流変更時の下流更新義務

上流ドキュメントを変更したら、同じ作業の中で下流への影響を確認する:

- 要求・要件の追加/変更 → 設計(画面一覧・アーキテクチャ)と見積もり(WBS)を確認
- 設計の変更(技術・構成) → 見積もり(開発費用・運用費用)を確認
- 影響がある下流ドキュメントはステータス行を `draft` に戻し、影響箇所に TODO を残すか即時更新する

## 見積もりの原則

- 単価・工数は docs/estimate/01-development-cost.md の単価表を使う
- 前提条件・除外事項を必ず更新する(スコープが変わったら特に)
- 金額を勝手に確定しない — 工数(人日)の算出まで行い、単価・バッファ率の最終判断はユーザーに確認する
