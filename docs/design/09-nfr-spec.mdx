## 実現方式詳細

### NFR-001: 性能(回答の応答)

#### 実現方式

- 問題データは出題開始前に学年単位でメモリに読み込み、回答時はメモリ上で判定する(I/O なし)
- 効果音は起動後の最初のタップで AudioContext をアンロックし、デコード済みバッファを保持して即時に再生する
- 回答ごとの IndexedDB 書き込みは行わず、セット完了時に 1 トランザクションでまとめて保存する
- 正誤表示のアニメーションは `transform` / `opacity` のみを使い、レイアウト再計算を起こさない

#### 測定・監視方法

- Playwright のテストで、タップから正誤表示までの時間を計測し 100ms 以内であることを確認する(CPU スロットリング 4 倍の条件で実施)
- 受け入れテストで実機(最も古い対応 iPad・Android 端末)で確認する

### NFR-002: 性能(初回読み込み)

#### 実現方式

- static export により HTML をビルド時に生成し、CDN から配信する
- 初回の取得対象はアプリ本体・フォント・問題データのみ(合計 約 2〜3MB、圧縮後)。音声は SCR-003 表示後に取得する
- Klee One は出題に使う文字(配当漢字 1,026 字・かな・記号)にサブセット化し、WOFF2 で配信する。`font-display: swap` で文字表示を待たせない
- 問題データは学年別ファイルに分割し、表示に必要な manifest を先に読み込む

#### 測定・監視方法

- Lighthouse(モバイル・4G スロットリング)で、学年選択画面が操作可能になるまでの時間を計測し 5 秒以内を確認する

### NFR-003: 可用性(オフライン)

#### 実現方式

- Serwist の precache で、アプリ本体・フォント・効果音・問題データを Service Worker インストール時に保存する
- 音声はランタイムキャッシュ(CacheFirst)。選択中の学年を優先し、残りの学年はバックグラウンドで順次取得する
- 新しいバージョンのデプロイ時は、新しい Service Worker を待機させ、出題中には切り替えない。次回起動時に有効化する
- 配信サーバーが停止しても、キャッシュ済みの端末は影響を受けない

#### 測定・監視方法

- Playwright のオフラインエミュレーションで、初回アクセス後に全学年の出題・結果保存ができることを E2E テストする
- 受け入れテストで、機内モードの実機(iPad・Android)で全学年を確認する

### NFR-004: 互換性

#### 実現方式

- ビルドの対象ブラウザ(browserslist)を対応範囲に合わせて設定する
- `navigator.storage.persist()` など対応状況が異なる API は、未対応でも動作を継続する(機能検出)

#### 測定・監視方法

- CI で Playwright を WebKit・Chromium の両方で実行する
- 受け入れテストの実機: iPad(iPadOS 最新)、iPhone(iOS 最新)、Android スマートフォン、Chromebook、Windows PC(Edge) {/* TODO: 検証端末の調達方法(自社保有 / 顧客貸与)を確認 */}

### NFR-005: ユーザビリティ(画面サイズ・タップ領域)

#### 実現方式

- DESIGN.md のブレークポイントを基準に、スマートフォン(〜640px)・タブレット(641〜1068px)・PC の 3 レイアウトを用意する
- 出題画面は向き(`orientation`)で縦積み / 左右配置を切り替える
- ボタンは共通コンポーネント化し、最小サイズ 44 × 44px(選択肢は高さ 72px 以上)を型で強制する

#### 測定・監視方法

- Playwright で主要画面のスクリーンショットを 360px・768px(縦横)・1280px で取得し、レビューする

### NFR-006: ユーザビリティ(操作回数)

#### 実現方式

- 起動時に前回のプロフィール・学年を復元し、SCR-003 から開始する
- 回答後は自動で次の問題へ進み、操作を求めない

#### 測定・監視方法

- E2E テストで、起動から出題開始までのタップ数が 3 以内であることを確認する

### NFR-007: ユーザビリティ(表記・文字サイズ)

#### 実現方式

- 画面文言は 1 ファイルに集約し、ルビ付きの記法(例: `{漢字|かんじ}`)で管理する
- 最小文字サイズ(本文 17px・ボタン 20px・出題の熟語 80px)を Tailwind のテーマトークンとして定義し、それ以下を使わない

#### 測定・監視方法

- 文言ファイルを自動チェックし、ルビのない漢字(1 年生の配当漢字を除く)を検出する

### NFR-008: アクセシビリティ

#### 実現方式

- 正誤は ⭕️/❌ 記号 + 枠色 + 正しい読みの文字表示の 3 つで伝える
- 読み上げ OFF・音声未取得の場合も、正しい読みは必ず文字で表示する
- OS の「視差効果を減らす」設定(`prefers-reduced-motion`)でアニメーションを無効化する
- feedback 色は白背景でのコントラスト比 4.5:1 以上

#### 測定・監視方法

- Lighthouse のアクセシビリティ監査、コントラストチェック

### NFR-009: セキュリティ

#### 実現方式

- Vercel 標準の HTTPS(TLS 1.2 以上)。`vercel.json` で HSTS を付与する
- `vercel.json` でセキュリティヘッダーを付与する
  - `Content-Security-Policy`: `default-src 'self'`、`connect-src 'self'`、`media-src 'self'`、`font-src 'self'`
  - `X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`Permissions-Policy`(カメラ・位置情報を無効化。マイクは九九の音声入力(FR-031)のため自サイトのみ許可 `microphone=(self)`)
- ユーザー入力はニックネームのみ。React の標準エスケープで表示し、HTML として解釈しない

#### 測定・監視方法

- リリース前にセキュリティヘッダーのチェックツールで確認する
- 依存ライブラリの脆弱性を GitHub の Dependabot で検知する。更新作業は保守契約がないためスポット対応とする

### NFR-010: プライバシー

#### 実現方式

- 外部ドメインへの通信を行わない(CSP の `connect-src 'self'` で強制)。利用統計・広告・外部フォント配信は使わない
- ニックネーム・学習データは IndexedDB にのみ保存し、送信処理を実装しない
- Cookie を使用しない

#### 測定・監視方法

- E2E テスト中のネットワークリクエストを記録し、自ドメイン以外への通信がないことを確認する

### NFR-011: 規模

#### 実現方式

- 静的配信のみとし、利用者数に応じたサーバー増強を不要にする
- 1 人あたりの初回転送量 約 35MB、年間合計 約 50〜100GB を想定(Vercel Pro の込み転送量内)

#### 測定・監視方法

- Vercel の Usage 画面で月次の転送量を確認する

### NFR-012: データ品質

#### 実現方式

- 問題データの作成フロー(機能設計 FR-021)で、検証スクリプト → 人手チェック 1 回目 → 別担当による人手チェック 2 回目を必須とする
- 検証スクリプトはビルド時にも実行し、失敗したらデプロイしない
- 生成した音声は全件を人が聴いて確認し、読み・アクセントの誤りを修正する(VOICEVOX のかな・アクセント指定で調整)
- 出題書体(Klee One)の字形が教科書体と異なる漢字がないか、人手チェック時にあわせて確認する
- チェック結果(担当者・日付)を問題データ原稿に記録する

#### 測定・監視方法

- 検証スクリプトのエラー 0 件、人手チェック完了率 100% をリリース条件とする
- リリース後の誤り報告は件数を記録し、修正リリースを行う

### NFR-013: 運用・保守

#### 実現方式

- 問題データ原稿(`content/`)と生成物(`public/data/`・`public/audio/`)をアプリのコードと分離する
- 原稿の修正 → スクリプト実行 → PR → Preview 確認 → マージで再リリースできる
- 問題 ID は公開後に変更しない。削除する場合は manifest の `removedQuestionIds` に記載する

#### 測定・監視方法

- 問題データのみを変更した PR で、アプリのコード変更なしにデプロイできることを受け入れテストで確認する

### NFR-014: データ保持

#### 実現方式

- 起動時(特にホーム画面アプリとして起動したとき)に `navigator.storage.persist()` を要求する
- iOS / iPadOS の Safari タブで初回起動した場合は、プロフィール作成前にホーム画面追加を案内する(Safari タブとホーム画面アプリでストレージが分離されるため)
- 設定画面(SCR-009)に、記録が消える条件(ブラウザのデータ削除、端末の変更、Safari タブでの長期間未使用)を説明する

#### 測定・監視方法

- 受け入れテストで、ホーム画面アプリの実機で記録が保持されることを確認する

### NFR-015: ライセンス

#### 実現方式

- SCR-009 に「クレジット」欄を設け、VOICEVOX のクレジット(「VOICEVOX:キャラクター名」)、Klee One のライセンス(SIL OFL 1.1)、利用ライブラリのライセンス一覧を表示する
- 依存ライブラリのライセンス一覧はビルド時に自動生成する
- VOICEVOX キャラクターの利用規約は採用時点の版を保存しておく

#### 測定・監視方法

- リリース前チェックリストで、クレジット表示と依存ライセンスに GPL 等の想定外ライセンスがないことを確認する
