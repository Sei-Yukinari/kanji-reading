## 機能詳細

### FR-002: 出題セットの生成

#### 入力

| 項目 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| mode | enum | ○ | practice / time_attack / review |
| grade | int | ○ | 1〜6 |
| unitId | string | practice のみ | 単元 ID |
| profileId | string | ○ | 学習履歴の参照に使用 |

#### 処理ロジック

1. 出題候補を決める
   - practice: 指定単元の全問題
   - time_attack: 指定学年の全問題
   - review: プロフィールの REVIEW_ITEM(指定学年)
2. 候補を優先度順に並べる(practice・review のみ)
   1. 未回答の読みの問題
   2. 学習中(連続正解 3 回未満)の読みの問題。直近の不正解が新しいものを優先
   3. 習得済みの読みの問題
3. 優先度の高い順に、同じ漢字が 1 セットに 2 回以上出ないように 10 問を選ぶ。同じ優先度内はランダム
4. 2 形式が偏らないよう、1 形式が 6 問を超えないように調整する
5. 候補が 10 問未満の場合(review で復習対象が少ない等)は候補数をそのまま問題数とする
6. 選択肢 4 つ(正解 + 誤答 3)の並び順をランダムにする

#### 業務ルール

- time_attack は優先度を使わず完全ランダム(公平な記録比較のため)
- 途中で「やめる」を選んだセットは SESSION・ANSWER・習得状況を保存しない

### FR-004〜FR-006: 出題形式と選択肢のルール

問題データ作成時に以下のルールを満たすことを、人手チェックと検証スクリプトで担保する。

| 形式 | 表示 | 曖昧さ排除のルール | 誤答の作り方 |
| --- | --- | --- | --- |
| 熟語(word) | 熟語 | 熟語としての読みが 1 つに定まるものだけを採用 | 構成漢字の別の読みの組合せ(例: 火山 → かやま)、連濁・促音の誤り |
| 文中(sentence) | 例文 + 出題漢字に下線 | 文脈で読みが 1 つに定まる例文だけを採用 | 同じ漢字の別の読み(文脈上は誤り)、音の似た読み |

- 選択肢はすべてひらがな(音読みもひらがなで表記)
- 誤答に、実在しない不自然な語を含めてもよいが、不適切な語(下品・差別的な語)は含めない
- 熟語・例文の出題対象以外の漢字は、その学年までに習う漢字ならそのまま表示、未習の漢字はルビ付きで表示する(FR-022)
- 単漢字 1 字の問題(旧 FR-003)は出題しない。原稿の `exclude`(出題しない読み)は人手チェック用の参考情報として残す

### FR-007: 正誤判定と自動遷移

#### 処理ロジック

1. 選択肢がタップされたら、以降のタップを無効化する
2. 選んだ選択肢と問題データの answer を比較して正誤を判定する(端末内処理、NFR-001)
3. 正誤を表示し、効果音を鳴らす(設定 ON の場合)
4. 正しい読みを表示し、読み上げる(設定 ON の場合)
5. ANSWER を一時保持し、READING_PROGRESS・REVIEW_ITEM の更新内容を計算する(保存はセット完了時にまとめて行う)
6. 表示時間(正解 1.0 秒 / 不正解 2.0 秒)経過後、または画面タップで次の問題へ進む

#### 業務ルール

- 読み上げ中に表示時間が経過した場合は、読み上げの完了を待たずに次へ進む(テンポを優先)
- 正解時: READING_PROGRESS.correct_streak を +1。3 以上で status = mastered
- 不正解時: correct_streak を 0 に戻し status = learning。REVIEW_ITEM に登録する
- review モードで正解した問題は REVIEW_ITEM から除去する

### FR-011: タイムアタック

#### 処理ロジック

1. 3 秒のカウントダウン後に 1 問目を表示し、計測を開始する
2. 計測は「問題表示から選択肢タップまで」の時間のみ合計する(正誤表示中は停止)
3. 不正解 1 問につき 5 秒を加算する
4. 10 問終了後、合計時間を BEST_RECORD と比較し、短ければ更新する

#### 業務ルール

- アプリがバックグラウンドに移った場合は計測を停止し、復帰時に「つづける / やめる」を選ばせる
- 記録は学年ごと・プロフィールごとに保持する

### FR-012: メダル・スタンプ

セット完了時に以下の条件を評価し、未獲得のメダルを付与する。メダルの種類は仮置きで、確定後に差し替える。

| メダル | 条件(仮置き) |
| --- | --- |
| はじめの いっぽ | 初めてセットを完了 |
| まんてん | れんしゅうで 10 問全問正解 |
| れんぞく 3 / 7 / 30 にち | 連続でセットを完了した日数 |
| たんげん クリア | 単元の全漢字が習得済み |
| がくねん マスター | 学年の全漢字が習得済み(学年ごと) |
| スピード スター | タイムアタックで自己ベストを 3 回更新 |

### FR-016: プロフィール

#### 入力

| 項目 | 型 | 必須 | バリデーション |
| --- | --- | --- | --- |
| ニックネーム | string | ○ | 1〜10 文字。前後の空白を除去。絵文字・記号も可 |
| アイコン | enum | ○ | 用意した 12 種類から選択 |

#### 業務ルール

- プロフィールは最大 4 件
- 削除時は確認ダイアログを表示し、そのプロフィールの学習データをすべて削除する
- 氏名など個人を特定する情報の入力を促す文言は使わない(例: 「なまえ」ではなく「ニックネーム」)

### FR-017: 端末内保存

- 保存先は IndexedDB。起動時に、ストレージの永続化をブラウザに要求する(要求が拒否されても動作は継続)
- セット完了時に SESSION・ANSWER・READING_PROGRESS・REVIEW_ITEM・BEST_RECORD・MEDAL_AWARD を 1 トランザクションで保存する
- 学習データのエクスポート・インポート機能は提供しない(対象外)
- iOS / iPadOS では Safari のタブとホーム画面に追加したアプリのストレージが分離され、Safari で付けた記録はホーム画面アプリに引き継がれない。このため iOS / iPadOS の Safari タブで初回起動した場合は、プロフィール作成の前に SCR-010(ホーム画面追加の案内)を表示する(「あとで」でスキップ可)

### FR-021: 問題データの作成と検証

#### 作成フロー

![作成フロー](/diagrams/design-04-functional-spec-01.svg)

#### 検証スクリプトのチェック項目(ビルド時に自動実行)

- 1,026 字すべてが KANJI に存在し、学年・単元が正しい
- すべての READING に 1 問以上の QUESTION がある
- 全問題で選択肢 4 つが互いに異なり、正解が誤答に含まれない
- すべての漢字に熟語問題が 2 問以上ある
- すべての漢字に出題する読みが 1 つ以上ある
- 選択肢がすべてひらがなである
- 問題文中の未習漢字にルビが付いている
- すべての問題の正解の読みに音声ファイルが存在する
- 問題 ID が既存リリースから削除・変更されていない(削除はリストで明示した場合のみ許可)

## エラーハンドリング

| エラーケース | 検知タイミング | メッセージ | システム動作 |
| --- | --- | --- | --- |
| IndexedDB が使えない(プライベートブラウズ等) | 起動時 | 「きろくが ほぞんできない せってい です」 | 学習は可能。メモリ上のストアで動作し、記録は保存しない |
| ストレージ容量不足 | 保存時 | 「きろくが ほぞんできませんでした」 | ANSWER の古いものを削除して再試行。失敗時はメッセージ表示 |
| 問題データ未取得かつオフライン | 学年選択時 | 「インターネットに つないでね」 | 該当学年を選択不可にする |
| 問題データの読み込み失敗(破損・配信更新直後のファイル名不一致) | 出題開始時 | 「もんだいが よみこめませんでした」 | manifest を取り直して 1 回だけ再取得を試みる。失敗時はメッセージ表示 |
| 音声の再生失敗 | 読み上げ時 | 表示しない | 読み上げをスキップして学習を継続 |
| 学習データのスキーマ移行失敗(新しいバージョンの DB が残っている等) | 起動時 | 「きろくを よみこめませんでした」 | 旧データは消さずに保持し、メモリ上のストアで起動する(記録は保存しない)。アプリ更新後に旧データで再開できる |
| ニックネーム未入力・11 文字以上 | 入力時 | 「1〜10もじで いれてね」 | 保存ボタンを無効化 |
