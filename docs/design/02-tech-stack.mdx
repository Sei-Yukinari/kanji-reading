## 選定方針

- フロントエンドはチームが習熟している **Next.js + TypeScript**、ホスティングは **Vercel** とする(顧客指定・2026/10/04 ヒアリング)
- サーバー処理を持たない静的 PWA とし、オフライン動作(FR-019, NFR-003)と運用費用の最小化(NFR-011)を両立する
- 学習データは端末外へ送信しない(NFR-010)。外部サービスへのデータ送信は行わない(利用統計も収集しない)
- 問題データ・音声の正確性(NFR-012)を、実行時ではなく **ビルド時の生成・検証** で担保する
- 3 ヶ月の納期に合わせ、保守が活発でドキュメントの多いライブラリを優先する

## 比較検討

### T-001: レンダリング方式

| 観点 | 候補A: static export(`output: 'export'`) | 候補B: 通常の Vercel デプロイ(サーバー機能あり) |
| --- | --- | --- |
| オフライン(FR-019, NFR-003) | ◎ 全ページがビルド時に HTML/JS 化され、まとめて precache できる | ○ 動的ルートの precache が難しい |
| サーバー不要(NFR-011) | ◎ Functions を使わない。Vercel 以外への移設も容易 | △ Functions の課金・障害の影響を受ける |
| 使えない機能 | 画像最適化(既定ローダー)、Server Actions、ISR、Route Handler 等 | なし |
| 総合 | **推奨**(承認待ち) | 非推奨 |

**推奨理由**: 本アプリはサーバー処理を必要とせず、static export の制約による実害がない。オフライン動作と運用費用の両面で有利。

**不採用理由の記録**: 候補B はサーバー機能が使えるが本要件では不要で、Functions の費用・障害点が増えるだけのため不採用。

### T-002: PWA / Service Worker

| 観点 | 候補A: Serwist | 候補B: next-pwa 系 | 候補C: 手書き Service Worker |
| --- | --- | --- | --- |
| Next.js 16 / Turbopack 対応 | ◎ `@serwist/turbopack` が対応 | × 本家は長期間更新なし。派生版は Serwist へ移行済み | ○ |
| precache | ◎ マニフェストを自動生成。追加エントリも指定可能 | — | △ ハッシュ付きファイルの列挙・更新処理を自作 |
| 保守性 | ◎ Workbox の fork。月次でメンテナンス | × | △ |
| 総合 | **推奨**(承認待ち) | 非推奨 | 非推奨 |

**推奨理由**: Next.js 最新版に対応し、Workbox 互換の precache・ランタイムキャッシュを使える唯一の活発な選択肢。

**不採用理由の記録**: 候補B は保守停止。候補C は precache マニフェスト生成と更新制御の自作コストが 3 ヶ月の納期に見合わない。

### T-003: 端末内ストレージ

| 観点 | 候補A: Dexie.js | 候補B: idb | 候補C: localStorage |
| --- | --- | --- | --- |
| 容量・構造化 | ◎ IndexedDB。インデックス・クエリ可 | ○ IndexedDB の薄いラッパー | △ 約 5MB・同期 API・文字列のみ |
| 開発効率 | ◎ スキーマのバージョン管理・マイグレーション、React 連携(liveQuery) | ○ | ◎ |
| ブラウザによる削除リスク | 3 候補とも同じ(リスク参照) | 同左 | 同左 |
| 総合 | **推奨**(承認待ち) | 非推奨 | 非推奨 |

**推奨理由**: プロフィール別の履歴・復習対象の抽出(FR-013, FR-016, FR-017)にクエリが必要で、スキーマ移行の仕組みも標準で持つ。

**不採用理由の記録**: 候補B はマイグレーション・クエリ機能を自作する必要がある。候補C は容量・同期 API の制約で解答履歴の保存に向かない。

### T-004: 読み上げ音声

| 観点 | 候補A: Web Speech API(ブラウザの音声合成) | 候補B: クラウド TTS で事前生成 | 候補C: VOICEVOX で事前生成 |
| --- | --- | --- | --- |
| 読みの正確さ(NFR-012) | × エンジン任せで読み誤りが起き得る。声も端末ごとに異なる | ◎ ひらがな入力で読みを固定でき、全件を人が聴いて確認できる | ◎ かな入力でアクセントまで調整でき、全件確認できる |
| オフライン(FR-019) | △ Chromebook・PC の Chrome はネットワーク音声。Android は音声データの追加が必要 | ◎ キャッシュ済みなら再生可 | ◎ 同左 |
| 子ども向けの親しみやすさ | △ | ○ ニューラル音声 | ◎ キャラクター音声 |
| 費用 | 0 円 | 無料枠内の見込み(超過時 約 $16/100 万字) | 0 円(クレジット表記が条件) |
| ライセンス条件 | — | 各社規約 | 「VOICEVOX:キャラクター名」のクレジット表記必須。キャラクター個別の規約にも従う |
| 総合 | 不採用 | 不採用 | **採用**(2026/10/04 ユーザー決定) |

**選定理由**: 事前生成により読み誤りを全件チェックで排除でき、オフラインでも全端末で同じ声で再生できる。キャラクター音声は子ども向けアプリと相性が良く、費用もかからない。

**不採用理由の記録**: 候補A は読み誤り・端末差・オフライン非対応があり NFR-012 / FR-019 を満たせない。候補B は品質面で同等だが、子ども向けの親しみやすさで候補C を優先した。

**採用条件**:

- 読み上げ対象は **正解の読みのみ**(例文全体は読まない)。問題 ID ではなく読みの文字列単位で重複を除いて生成する(想定 約 3,000〜5,000 本)
- 形式: AAC(.m4a)モノラル 32kbps。平均 1.5 秒で約 6KB/本、全体で約 20〜30MB、学年あたり約 3〜6MB
- 使用キャラクターは利用規約で商用利用・クレジット表記のみで使えるものから選定する。**ずんだもん(ノーマル)を仮採用**(2026/10/04)し、クレジット「VOICEVOX:ずんだもん」を設定画面に表示する。キャラクターを変える場合は `web/src/audio/voice-config.ts` の話者 ID とクレジットを差し替え、音声を再生成する {/* TODO: ずんだもんの採用について顧客の了承を得る */}
- ひらがな 1 語でも VOICEVOX が助詞(「は」→「わ」)や複数の句として解析することがあるため、生成時に解析結果のカナを読みと照合し、一致しない場合はカナ指定で読みを固定する
- 生成は VOICEVOX エンジンをローカル(開発 PC)で実行するスクリプトで行い、生成物をリポジトリにコミットする

### T-005: 効果音再生

| 観点 | 候補A: Web Audio API 直接 | 候補B: Howler.js | 候補C: use-sound |
| --- | --- | --- | --- |
| iOS の自動再生制限 | ○ 最初のタップで `AudioContext.resume()` する処理を自作(数十行) | ◎ 自動でアンロック | ◎(内部は Howler) |
| 保守状況 | ◎ 標準 API | △ 2023 年以降リリースなし | △ |
| 遅延(NFR-001) | ◎ デコード済みバッファで即時再生 | ◎ | ◎ |
| 総合 | **推奨**(承認待ち) | 非推奨 | 非推奨 |

**推奨理由**: 追加依存なしで低遅延に再生できる。読み上げ音声も同じ AudioContext で再生し、自動遷移中もアンロック状態を保てる。

**不採用理由の記録**: 候補B・C は便利だが保守が停滞しており、必要な処理量が少ないため依存を増やす利点が小さい。

### T-006: 利用統計

| 観点 | 候補A: Vercel Web Analytics | 候補B: Umami Cloud | 候補C: 収集しない |
| --- | --- | --- | --- |
| プライバシー(NFR-010) | ○ Cookie 不使用 | ○ Cookie 不使用 | ◎ 外部送信なし |
| 費用 | Pro に含まれる | 無料枠あり | 0 円 |
| 運用への影響 | KPI を計測できる | 同左 | 利用状況・KPI を計測できない |
| 総合 | 不採用 | 不採用 | **採用**(2026/10/04 ユーザー決定) |

**選定理由**: 顧客判断により利用統計は収集しない(REQ-017 を Won't に変更)。外部送信がなくなり、プライバシーポリシーでの外部送信の公表対応も不要になる。

**不採用理由の記録**: 候補A・B はいずれも要件上の問題はないが、収集自体が不要と判断されたため不採用。将来 KPI 計測が必要になった場合は候補A を第一候補とする。

### T-007: 出題漢字の書体

| 観点 | 候補A: Klee One | 候補B: UD デジタル教科書体 | 候補C: OS 標準ゴシック |
| --- | --- | --- | --- |
| 学校で習う字形との一致 | ○ 教科書体に近いペン字系の書体 | ◎ 教科書体そのもの | × とめ・はね・はらいが異なる |
| 費用・ライセンス | ◎ SIL Open Font License(無償・同梱可) | △ Web フォントとして使うには有償ライセンスが必要 | ◎ |
| 容量 | ○ 使用文字(配当漢字・かな・記号)にサブセット化して軽量化 | ○ | ◎ 0 |
| 総合 | **採用**(2026/10/04 ユーザー決定) | 不採用 | 不採用 |

**選定理由**: 無償で同梱でき、ゴシック体よりも学校で習う字形に近い。出題文字はビルド時に確定しているため、サブセット化で容量を抑えられる。

**不採用理由の記録**: 候補B は字形の正確さは最良だが有償ライセンスが必要。候補C は字形が学習内容と一致しない。

**採用条件**: Klee One の字形が教科書体と異なる漢字がないかを、問題データの人手チェック時にあわせて確認する。UI 文言は OS 標準ゴシックのまま。

### T-008: スタイリング

| 観点 | 候補A: Tailwind CSS | 候補B: CSS Modules |
| --- | --- | --- |
| 開発速度 | ◎ | ○ |
| DESIGN.md トークンの適用 | ◎ テーマ変数として一元定義できる | ○ CSS 変数で定義 |
| レスポンシブ対応(NFR-005) | ◎ コンテナクエリを標準で利用可 | ○ |
| 総合 | **推奨**(承認待ち) | 非推奨 |

**推奨理由**: DESIGN.md のトークン(色・角丸・余白)をテーマに定義して全画面で再利用でき、縦横・端末サイズ対応も速い。UI コンポーネントライブラリは使わず、確認ダイアログ等のみ shadcn/ui からコードを取り込む。

**不採用理由の記録**: 候補B でも実現できるが、トークン適用とレスポンシブ対応の記述量が多い。

### T-009: テスト

| 観点 | 候補A: Vitest + Playwright | 候補B: Jest + Cypress |
| --- | --- | --- |
| Next.js / TypeScript との相性 | ◎ | ○ 設定が多い |
| iOS Safari 相当の確認 | ◎ Playwright の WebKit で確認可。オフラインのエミュレートも可 | △ WebKit 非対応 |
| 総合 | **推奨**(承認待ち) | 非推奨 |

**推奨理由**: 問題データの検証スクリプト(NFR-012)を Vitest で自動化でき、Playwright で iOS 相当・オフライン動作の E2E を実行できる。

**不採用理由の記録**: 候補B は WebKit で動作確認できず、iOS が主要ターゲットの本件に合わない。

### T-010: 問題データの元データ

| 観点 | 候補A: 公的資料(配当表・常用漢字表・音訓の段階別割り振り表) | 候補B: KANJIDIC2 |
| --- | --- | --- |
| 「小学校で扱う読み」の判定 | ◎ 段階別割り振り表で直接判定できる | × 学校段階の情報がない |
| ライセンス | ◎ 告示は著作権の対象外。割り振り表は政府標準利用規約(要確認) | △ CC BY-SA 4.0。派生データに継承義務が生じるおそれ |
| 総合 | **推奨**(承認待ち) | 照合用に限定(配信データには含めない) |

**推奨理由**: 出題範囲・読みの範囲を一次資料で確定でき、配信データのライセンスもクリーンに保てる。

**不採用理由の記録**: 候補B は学校段階の情報がなく、SA 条項が問題データ全体に及ぶリスクがあるため、人手チェック時の照合用にとどめる。

### T-011: 九九の音声入力

| 観点 | 候補A: Web Speech API(SpeechRecognition) | 候補B: 端末内の音声認識モデル(WASM) | 候補C: クラウド音声認識 API |
| --- | --- | --- | --- |
| 追加費用 | ◎ なし | ◎ なし | × 従量課金・API キーの管理が必要 |
| オフライン | × 多くのブラウザで通信が必要 | ◎ 動作する | × 通信が必要 |
| 対応ブラウザ | △ Chrome・Edge・Safari(iOS 14.5 以降)。Firefox は非対応 | ○ 主要ブラウザ | ◎ 主要ブラウザ |
| 配信サイズ | ◎ 0 | × モデルが数十 MB 以上 | ◎ 0 |
| 学習データを端末外へ送らない方針(NFR-010) | △ ブラウザ提供元の認識サーバーへ音声が送られる場合がある | ◎ 送らない | × 自前で送信する |
| 総合 | **採用** | 将来の検討候補 | 不採用 |

**採用理由**: 答えは 1〜81 の数だけで、追加費用と配信サイズなしで実現できる。使えない環境では数字キーで全機能を使えるため(NFR-016)、上乗せ機能として扱う。

**不採用理由の記録**: 候補B は配信サイズが PWA の初回読み込みに見合わない。候補C は費用と送信の管理が必要で、本件の方針(サーバーを持たない)に合わない。

**注意**: 音声の送信はブラウザの機能によるもので、アプリから学習記録を送るものではない。設定画面のクレジット欄で、音声で答えるときはブラウザの音声認識を使うことを案内する。

## リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| `@serwist/turbopack` が static export と組み合わせて動かない | FR-019 の実現方式に影響 | 開発冒頭で技術検証(1 人日)。不可の場合はビルド後の `out/` に Serwist の injectManifest を適用する方式に切り替える |
| iOS で Safari タブとホーム画面アプリのストレージが分離。Safari タブでは 7 日間未使用で記録が削除される | 学習記録の消失(NFR-014) | iOS の Safari タブでは初回にホーム画面追加を案内(FR-020)。ホーム画面アプリ起動時に `navigator.storage.persist()` を要求 |
| iOS の消音スイッチ ON 時に Web Audio が鳴らない場合がある | FR-008, FR-009 | 技術検証(0.5 人日)。鳴らない場合は「おとが でないときは マナーモードを かくにん」の案内を設定画面に表示 |
| VOICEVOX キャラクターの規約変更・クレジット表記への顧客の不同意 | FR-009 | キャラクター選定時に規約を保存。不同意の場合はクラウド TTS(T-004 候補B)へ切替(生成スクリプトを差し替えるだけで済むよう抽象化) |
| Vercel Hobby プランは商用利用不可 | 運用費用 | Pro プラン($20/席/月)で契約する。契約名義(顧客 / 自社)を見積もり前に確認 {/* TODO: 契約名義を確認 */} |
| 生成 AI による問題下書きの誤り・既存教材の例文の再現 | NFR-012、著作権 | 機械検証 + 2 回の人手チェック。既存教材・問題集の例文を入力に使わない |
| Next.js 16 系のセキュリティリリース(月次) | 保守 | 保守契約は締結しない(スポット対応)。静的配信でサーバー側の攻撃面は小さいが、年 1〜2 回のセキュリティ更新のスポット発注を顧客に推奨する |
| 利用統計を収集しないため KPI を計測できない | 効果測定 | 本開発では送信処理を実装しない(NFR-010)。将来 KPI 計測が必要になった場合は T-006 候補A の追加を別途見積もる |
